## Задача сайта и контент

- Помочь человеку понять, кто Вера, и связаться с ней по поводу теннисной тренировки.
- Пока Вера готовит материалы, развиваем небольшую основу. Не добавляем пустые блоки ради длины страницы.
- Имя и профессия подтверждены Антоном. Москва и запись через директ подтверждены профилем Веры. Другие факты — только со ссылкой на источник в `docs/CONTENT.md` или после сообщения Веры/Антона.
- Не придумываем стаж, разряды, сертификаты, цены, корты, аудиторию, результаты учеников, отзывы и доступные места. 12 лет лёгкой атлетики не означают 12 лет тенниса или тренерского опыта.
- Старые объявления о группах не считаем текущим расписанием. Telegram из биографии пока не считаем подтверждённым каналом записи.
- Сохраняем авторскую речь, имена и смысл цитат. Редакционный текст не выдаём за цитату Веры.
- Используем реальные материалы Веры. У каждого файла есть происхождение в `docs/ASSETS.md`; на сайте файлы локальные. Не подменяем человека стоком или генерацией.
- Исходники большого размера, снимки аккаунта и временные подписанные URL не коммитим. Не переносим в проект личные сообщения, контакты третьих лиц и сведения из интерфейса аккаунта.

## Визуальная система

- Типографика, фотография и общая сетка формируют характер сайта. Кортовая зелень, тёплая светлая поверхность и небольшой акцент теннисного мяча поддерживают тему.
- Первый экран: имя, профессия, город, реальная фотография, понятный путь к контакту.
- Плотность определяется имеющимся содержанием. Не размножаем карточки, лозунги и декоративные цифры.
- Цвет, отступы и типографика задаются CSS-токенами. Повторяем удачные компоненты и состояния.
- Адаптивность плавная: `min()`, `max()`, `clamp()`, гибкие сетки. Меняем компоновку там, где содержание перестаёт помещаться; не скрываем переполнение для маскировки ошибки.
- Иконка должна иметь смысл. У действия есть понятная подпись; декоративные SVG скрыты от скринридера.
- Русская типографика: «ёлочки», длинное тире, строчное «вы». Неразрывные пробелы защищают смысловые группы, а не искусственный перенос строки.

## Реализация

- Авторский HTML и CSS находятся в `site/`. `dist/` — результат сборки, его не редактируем и не коммитим.
- Для этой стадии достаточно статического сайта без runtime-зависимостей. Контент и контакт доступны без JavaScript.
- Сохраняем семантику: один h1, последовательные заголовки, landmarks, skip-link, осмысленные alt, видимый focus, ссылки для переходов.
- Проверяем от 320 px, увеличение текста, клавиатуру, prefers-reduced-motion и системную тёмную тему. Интерактивные цели — не менее 44 px.
- Фото имеют width/height; главное изображение загружается приоритетно, второстепенное лениво. Никаких Instagram embeds и сторонних скриптов без задачи.
- Не добавляем формы, аналитику, сбор данных или cookie-баннер, пока для них нет реального требования.

## Проверка и выпуск

1. `npm run check` и `npm run build`.
2. Посмотреть всю затронутую композицию в реальном браузере на мобильной и большой ширине; проверить обе системные темы, переход к контакту и фокус.
3. Для точечной правки — одна задача, один релевантный визуальный контроль. Полный проход — один раз перед публикацией.
4. После публикации проверить GitHub Actions, открыть URL с cache-busting, проверить загрузку локальных ресурсов и консоль. Зелёный CI не заменяет визуальную приёмку.
5. Записать выполненные проверки и ограничения в `docs/QA.md`. Не выдавать эмуляцию за физическое устройство или ручной скринридер.

Текущая версия — основа для обсуждения. `noindex` сохраняем до готовности контента и решения о полноценном запуске. `noindex` не является ограничением доступа.
